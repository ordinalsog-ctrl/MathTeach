# Support Response Matrix Template

## Zweck

Dieses Template dient als Standardform fuer alle spaeteren
`profile-specific response matrices`.

Es soll sicherstellen, dass jede Matrix:

- nicht-diagnostisch bleibt
- erklaerbare Regeln verwendet
- auf vorhandene Quellenanker verweist
- und direkt in spaetere Code- und Plannerlogik uebertragbar ist

## 1. Profilname

- `profile_slug`
- `human_name`
- `scope`

## 2. Safety Frame

- nicht-therapeutisch
- nicht-diagnostisch
- selbstbeschriebene Bedarfe haben Vorrang
- Tutorreaktionen bleiben revidierbar

## 3. Support Signals

Liste der primaeren Signale, auf die diese Matrix reagiert.

Beispielform:

- `signal_name`
  - `what_it_looks_like`
  - `what_it_does_not_mean`

## 4. Candidate Response Settings

Jede Zeile sollte diese Felder haben:

- `dimension`
- `candidate_setting`
- `why`
- `source_anchors`
- `validation_note`

## 5. Runtime Preferences

- bevorzugte Tutor-Modi
- zu vermeidende Tutor-Modi
- Voraussetzungen fuer Moduswechsel

## 6. External Scaffolds

- welche externen Hilfen aktiv gesetzt werden
- wann sie reduziert werden duerfen
- wann sie stabil bleiben sollen

## 7. Misconception Handling

- typische Fehlermuster
- bevorzugte Fehlerreaktion
- wann zur Voraussetzung zurueckgegangen wird

## 8. Progress Signals

- woran erkennt das System, dass die aktuelle Einstellung hilft
- woran erkennt das System, dass nachjustiert werden muss

## 9. Source Anchors

Nur lokale Projektquellen oder klar referenzierte Startquellen verwenden.

## 10. Open Questions

- was noch unsicher ist
- welche Regeln spaeter verifiziert werden muessen
- welche Kombinationseffekte noch offen sind
